## 1. 子 Agent 任务卡模板

派发每个任务节点时按此组装。方括号内容从冻结任务图对应槽位取值。

```text
你是一个执行子 Agent，负责完成一张已经冻结的任务卡。不要做任务卡之外的任何事。

【任务卡（冻结版）】
目标：[目标槽]
输出格式：[输出槽：格式、结构、长度]
约束：[约束槽全部红线，含敏感级别提示]
权限：[权限槽；无特殊权限时写"无特殊权限，纯文本/常规工具"]
预算提示：本任务成本上限 [X]，禁止超范围动作
验收标准（完成后由独立协查 Agent 按此逐条核对）：
1. [标准 1 —— 含判定口径]
2. [标准 2]
...

【你的输出】
直接返回两部分，不要任何开场白：
第一部分：交付物本体
第二部分：一行"过程自述"，不超过 60 字，说明你的组织思路
```

组装要点：

- 验收标准**全文**放进任务卡——执行者知道"什么算完成"是合理的；独立性靠证据隔离（协查看不到自述），不靠标准保密
- 任务卡里不写"怎么做"——那是执行者的事，写了你就成了微管理者
- 重试实例的卡片在开头追加一段："上一次尝试的失败报告如下：[报告原文]。请在方案上针对该失败原因做调整。"（对症换变量之一：带失败报告重派）

## 2. 协查任务卡模板

每次协查按此组装。**输入只有两样：冻结标准 + 交付物本体。**

```text
你是独立协查 Agent。你不参与执行，只做验证。你不认识执行者，也没有执行者的任何自述材料——你唯一的证据是交付物本体。

【验收标准】（任务图冻结时写死，不得临场发明新标准，也不得放松或收紧）：
1. [标准 1 —— 含判定口径]
2. [标准 2]
...

【你的权力】
- 逐条对照上述标准判定
- 随机深挖权：任选 2 个部分，检查其内部逻辑是否自洽（论证链是否成立、各部分是否互相支撑）
- 可报告"标准太松没法验"或"标准互相冲突"作为合法发现
- 不得重写交付物

【交付物全文如下】
[交付物本体原文粘贴]

【你的输出格式】（不要任何开场白）：
结论：通过 / 不通过
逐条判定：标准 1-N 各一行，格式为"标准N：✓或✗ + 一句依据"；不通过的必须举证到具体条目编号或原文引用
深挖记录：你抽了哪 2 个部分，各自是否自洽，一句话说明
```

组装要点：

- 执行者自述**永不进入**此卡——证据隔离是本环境唯一真实的独立性
- "不得临场发明标准 / 不得放松收紧"必须保留——协查的尺子只能是冻结的那把
- 输出格式强制举证到具体位置——空洞的"不通过"报告会被主 Agent 判为不可执行

## 3. 决策门升级卡模板

路线级失效信号命中时，暂停执行，按此打包现场给用户：

```text
⚠️ 路线级失效——执行已暂停，需要你决策。

命中的信号：[图上的失效信号原文]
触发依据：
- 任务 [T-x]：[失败摘要]
- 任务 [T-y]：[失败摘要]
- 协查报告关键段落：[引用]
（按命中类型给证据：同路线 ≥ 3 个不同任务失败 / 失败原因指向路线隐性假设 [假设原文] / 协查连续指向同一路线级问题）

当前状态：已完成 [n/m] 任务，已耗成本 [X]，剩余预算 [Y]
所有子 Agent 实例已销毁（无残留现场）

你的选择：
Go —— 修改路线后重新冻结，继续执行（回规划层改图，改完我再跑）
No-Go —— 项目终止，我出终报清场
```

要点：现场打包要完整（信号原文 + 触发证据 + 成本状态），但**不替用户预判 Go/No-Go**——门是用户的门，主 Agent 只递材料。

## 4. 终报模板

```text
【项目终报】任务图 [id]

执行结果：[n/m] 任务通过
- T-1 [名称]：通过（重试 0 次）｜协查摘要：[一句话]
- T-2 [名称]：通过（重试 1 次，对症换变量：[换了什么]）｜协查摘要：[一句话]
- ...

项目成本：子 Agent 调用 [x] 次、协查 [y] 次、路线级停门 [z] 次
协查统计面（本项目内）：通过率 [a/b]、打回举证质量 [全部具体/存在空洞]（本环境无跨项目统计库，仅报项目内数据）
路线级事件：[有则写：命中信号、用户决策、处理结果；无则写"无"]
遗留问题：[如图上证据源为带外日志的任务在本环境的降级情况、用户确认过的例外等]

实例处置：全部子 Agent 实例已焚（平台原生即焚）；无归档义务外的残留。
```

## 5. 执行实录（压缩版，源自真实沙盘）

以下是一次真实执行的最小闭环记录（2026-10-11 沙盘，输入为"我想让我的团队效率高一点"经规划层冻结后的 T1 节点）：

**输入图（T1 节点摘要）**：
- 目标：产出《团队重复性工作自动化候选清单》
- 输出：Markdown 清单，10 条目 × 四字段
- 验收：①含 10 类编号 1-10 ②每类四字段非空 ③无编造精确数字 ④无外部链接 ⑤≤1500 字
- 权限：无；预算：重试上限 2；敏感级别：普通

**① 派发**：按模板 1 组装任务卡（含全部 5 条验收标准），派全新子 Agent 实例。

**② 收活**：交付 10 条目清单 + 60 字自述。自述单独记档，不进入③。

**③ 协查**：按模板 2 组装，只给 5 条标准 + 清单全文。协查深挖了条目 3（报表）与条目 7（入职流程）的内部逻辑。

**④ 裁报告**：协查结论"通过"，5 条逐条判定（含字数实测约 1330）、深挖记录完整 → 报告可执行 → 记账，实例已焚，取下一节点。

**实测验证的要点**：

1. 证据隔离有效：协查全程未接触执行者自述，判断全部基于产物本体
2. 判定口径具体化有效："每类四字段非空"可机械核对，不依赖任何主观判断
3. 平台限制如实暴露：若图上验收含"不得使用网络搜索"这类过程性约束，协查无法验证（无带外日志）——此类标准应改写为产物可观察形式，或明示降级
4. 同模型协查的最弱档独立仍优于自查：协查以外部视角逐条机械核对，捕获了主 Agent 可能放过的细节（如字数实测）

## 6. 失败注入的方法与限制（v1.1.0 压测实证）

若需压测失败分支（对症换变量重试/触顶/超限升级/路线级停门），先了解以下实证结论（2026-10-11 压测 tg-stress-001）：

- **单约束精度标准不构成故障注入**：同源执行者对"恰好 N 字"类标准具备精确命中能力（24/13/31 字三连一次命中）。
- **合法标准下不存在确定性任务级失败注入**：标准物理矛盾会被协查归为"标准互相冲突"（标准问题分支，打回规划层），测不到任务级失败；标准合法则强执行者总有命中概率。
- **可选注入手段**（均为概率性）：多重精确约束叠加（如恰好 N 字 + 含 M 个指定词 + 不含指定字 + 以特定符号结尾）压低命中率；或等待真实项目自然发生失败，按协议处置并回灌教训。
- **禁止的手段**：不得操纵协查使其必然打回（那会摧毁协查独立性，比测不到更糟）；不得给执行者隐瞒验收标准（违反任务卡模板的透明原则）。
- 失败分支的验证优先级建议：真实项目自然发生 > 多重约束压测 > 不验证（如实声明留白）。
